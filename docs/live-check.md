# 装备页实机复测步骤（不是实机通过记录）

用 `Survival` 打开装备页。已占用栏应随原生装备栏显示网络文字（含 BOT），空栏没有看板。移动鼠标、关闭并重开、局内按 `Esc`：检查文字不跳位、不重复。

若某栏不显示，先在 Info 查 `[槽位网络]` 的 `waiting-equipment`、`waiting-watermark` 或 `waiting-button-row`，并检查 Warning 的完整异常。自 1.1.11 起，要查卡片是否就绪，请在 BepInEx 的日志输出中启用 Debug，查找 `native-tmp/compare-row`（按钮行）、`native-tmp/retained-row`（沿用位置）或 `native-tmp/reference-row`（备用行）的 `glyphs` 和 `active`。Info 没有这些就绪行属正常；有字形仍需目视确认。

只有本机和 BOT 时，不应把整机网卡数值当作游戏流量。真人加入后再看几个采样窗口，区分游戏载荷、网卡、待采样和真实空闲；复测多人上报可用以下步骤。

1. **大厅零点击**：仅 B 安装，进入 A 的装备大厅，不点按钮。观察至少 15 秒：A 的队友卡应显示「无近期兼容报告」；有游戏缓存时显示往返估值和采样时间未知，没有缓存则显示往返未知。不要指望这一栏出现合作探针波动或缺号率。
2. **合作但无房主插件**：C 安装兼容 DLL 后加入。B 与 C 的队友卡应区分已收报告但探针不可用、等待回声、测得往返上限；不从 B/A、C/A 两条链路推算 B/C 延迟。首个有效回声不应凭空产生波动；缺收与缺发可以只有一边有数。离开、重进或换房后，旧报告不能当作当前值。
3. **每栏入口**：加入第四位真人，再用 BOT 替换一席。四名真人应各有一个「模组对照」、没有「网络」按钮；BOT/空位无入口。记录 16:9 与超宽各一张截图，特别看最右栏、长昵称和装 Localia 时；点每个入口都能辨认选中的人。检查没有挡住服装、装备或同栏其他控件。
4. **拖动与光标**：用能溢出的长清单。在关闭按钮、列表和轨道上移动，指尖应与命中一致。抓住滑块拖到底，横向移出轨道再松手；应能见最后一行，不触发后方装备。单格滚轮只滚一次；`Home/End/PgUp/PgDn`、`F`、点击关闭、`Esc` 和重开均有效。短清单无滑块。开着表切页/切出窗口，不应留拖动归属。
5. **弹窗和退场**：打开服装/装备选择，网络文字不能压住弹窗；离开装备页去主菜单，常显层和入口消失。无须提供任何 IP、Steam ID 或完整日志；把姓名打码，保留各行的角色、方向、单位和年龄即可。
